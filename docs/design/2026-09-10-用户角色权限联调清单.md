# 用户、角色与权限管理联调清单

## 当前边界

门户不维护第二套身份库。统一身份服务仍是用户身份、账号状态和角色分配的权威来源；门户后端负责鉴权、租户范围校验、受控代理和审计。当前前端的本地 mock 仅用于完成操作流验证，不能替代正式身份服务。

ABAC 访问策略继续由策略服务维护。本页展示策略及其作用范围，暂不直接编辑策略，避免角色分配与属性策略出现两套相互覆盖的配置入口。

## 已在本地模拟验证的接口

| 接口 | 用途 | 前端行为 |
| --- | --- | --- |
| `GET /admin/iam/users` | 查询用户；支持 `keyword`、`status`、`role`、分页 | 用户检索、状态与角色筛选 |
| `GET /admin/iam/roles` | 获取角色、职责和权限清单 | 角色目录、权限详情、成员统计 |
| `PUT /admin/iam/users/{userId}/roles` | 更新用户角色，提交 `{ roles: string[] }` | 配置角色；角色不能为空 |
| `PUT /admin/iam/users/{userId}/status` | 更新状态，提交 `{ status: 'ACTIVE' \| 'DISABLED' }` | 启用或停用用户 |
| `GET /admin/iam/audit-logs` | 查询最近的权限变更审计 | 展示角色和账号状态变更记录 |
| `GET /admin/abac-policies` | 查询访问策略 | 展示角色权限之外的属性限制 |

## 正式环境联调要求

1. 门户后端以当前登录管理员的身份和租户范围调用统一身份服务管理接口；浏览器不得直接调用身份服务的管理员接口，也不得暴露管理员凭据。
2. 角色更新必须校验角色编码、操作者权限、目标用户所属租户和最后一名有效“门户管理员”保护规则；失败时返回可识别的 `403`、`409` 或 `422`。
3. 账号状态变更仅影响门户授权状态，还是同步禁用统一身份账号，需要由身份服务接口明确语义；前端以接口返回的最终状态为准。
4. 审计至少记录操作者、目标用户、租户、操作时间、请求关联号，以及角色/状态的变更前后值；查询应按权限和租户隔离。
5. 角色目录、权限码和 ABAC 策略由正式服务返回；前端仅做中文展示和操作编排，不在代码中固化授权判定。

## 联调验收场景

1. 管理员按姓名、状态、角色筛选用户，结果仅包含其可管理租户内的账号。
2. 为用户增删角色后，用户列表角色标签、角色成员数和审计记录一致；刷新页面后数据仍正确。
3. 停用和启用用户后，状态统计、用户列表和审计记录一致；停用最后一名有效门户管理员被拒绝且给出明确提示。
4. 角色权限抽屉与后端返回的权限码一致；ABAC 策略展示可解释角色权限之外的密级、租户、项目等限制。
